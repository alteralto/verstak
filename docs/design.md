# Устройство и план

## Решения (21.10.2026)

| Вопрос | Решение |
|---|---|
| Над чем работает | Над собой: тикеты про сам верстак. Другие репозитории — нет, persona-agent и unionclef в запретном списке |
| Чем писать код | Свой слой на Go (тикет, клон, проверки, коммит, отчёт) + Codex как исполнитель |
| Персонаж | Пока не выбран, возможно хоббит |
| MVP | Текст. Голос — позже |
| Репозиторий | Отдельный приватный |
| Требования трека | Спросить лектора: сроки, критерии, формат сдачи, нужен ли журнал прогресса |

## Принципы

1. **Никакого хардкода поведения.** Агент получает инструкцию и документацию, как сотрудник.
2. **Говорит тот, кто проверил.** «Сделано» — только после зелёных проверок в прогоне верстака.
3. **Защиты не ослабляются.** Запретный список, клон без remote, коммит только после зелёных
   проверок. Тикет, который просит это ослабить, агент не выполняет, а выносит в открытые вопросы.
   Правку защит смотрит разработчик.
4. **Самодоработка без риска.** Агент правит клон, а работает бинарь из основного репозитория.
   Новая версия попадает в работу, только когда разработчик забрал ветку и пересобрал бинарь.
5. **Всё измеряется.** У каждого шага есть время, у каждого раунда — токены, включая кэш.

## Этапы

1. **MVP (сделано).** CLI: тикет-файл → клон → Codex → проверки → повтор с ошибками → коммит →
   отчёт и трасса. Запретный список. Тесты на поддельном агенте.
2. **Первый живой прогон.** Тикет `tickets/example-own-tests.md`: агент пишет модульные тесты
   для собственных пакетов. Смотрим время, токены и качество, это базовая точка для замеров.
3. **Песочница Docker.** Образ с Go и Codex CLI, монтируются только клон (на запись) и
   авторизация Codex (на чтение). Сеть — только к API модели. Нужно разрешение: запуск Docker
   Desktop, сборка образа.
4. **Очередь и «лаборатория».** Агент сам пишет тикеты о том, что мешало ему в прошлых прогонах
   (по трассам и NOTES.md). Разработчик решает, какие пустить в работу.
5. **Персонаж и голос.** Характер (возможно, хоббит), быстрое подтверждение («щас гляну»),
   результат позже и в том же характере.

## Метрики

| Метрика | Что это |
|---|---|
| T_task | от тикета до отчёта, p50/p90 по классам задач |
| Раунды | сколько раз пришлось возвращать красные проверки |
| Доля готовых | done / все тикеты; отдельно — сколько веток разработчик принял |
| Токены и кэш | input, cached, output на тикет; кэш внутри сессии ≥ 70 % |
