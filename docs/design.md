# Устройство и план

## Решения (21.10.2026)

| Вопрос | Решение |
|---|---|
| Кто персонаж | Пыхтун чинит сам себя: тикеты о его поведении в игре, правки в persona-agent |
| Чем писать код | Свой слой на Go (тикет, клон, проверки, коммит, отчёт) + Codex как исполнитель |
| MVP | Текст. Голос подключаем, когда цикл работает |
| Репозиторий | Отдельный приватный, с кодом Minecraft-агента не смешиваем |
| Требования трека | Спросить лектора: сроки, критерии, формат сдачи, нужен ли журнал прогресса |

## Принципы

1. **Никакого хардкода поведения.** Агент получает инструкцию и документацию, как сотрудник. В
   инструкции прямо запрещено реагировать на конкретные слова (это главный постулат лекции).
2. **Говорит тот, кто проверил.** «Починил» — только после зелёных проверок в прогоне верстака.
3. **Цель неприкосновенна.** Агент работает в клоне без remote, разработчик забирает ветку сам.
4. **Всё измеряется.** У каждого шага есть время, у каждого раунда — токены, включая кэш.
   Сравниваем прогоны между собой.

## Этапы

1. **MVP (сделано).** CLI: тикет-файл → клон → Codex → проверки → повтор с ошибками → коммит →
   отчёт и трасса. Тесты на поддельном агенте: один раунд, повтор после красных проверок, красное
   не коммитится, «без изменений», повторный запуск в ту же папку.
2. **Первый живой прогон.** Пример тикета `tickets/example-takeoff-quiet.md` на persona-agent.
   Смотрим время, токены и качество правки: это базовая точка для всех следующих замеров.
3. **Песочница Docker.** Образ с Go и Codex CLI, монтируются только клон (на запись) и
   авторизация Codex (на чтение). Сеть — только к API модели. Нужно разрешение: запуск Docker
   Desktop, сборка образа.
4. **Тикеты из игры.** Игрок говорит Пыхтуну «запиши тикет: …». Связь с persona-agent — через
   папку входящих тикетов или HTTP, без общего кода. Результат возвращается строкой «Пыхтун
   говорит» в чат игры.
5. **Мастерская в Minecraft** (образец — AgentCraft: доска задач, вопросы игроку, приём diff).
   Пока агент работает, Пыхтун стоит у верстака, на табличках видны тикеты и статусы. Ветку
   принимает разработчик командой.
6. **Голос и быстрый ответ.** Сразу короткое подтверждение («щас гляну»), результат позже, в том же
   характере (уровни 0–1 из разбора лекции).

## Метрики

| Метрика | Что это |
|---|---|
| T_task | от тикета до отчёта, p50/p90 по классам задач |
| Раунды | сколько раз пришлось возвращать красные проверки |
| Доля готовых | done / все тикеты; отдельно — сколько веток разработчик принял |
| Токены и кэш | input, cached, output на тикет; кэш внутри сессии ≥ 70 % |
