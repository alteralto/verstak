# Изоляция агента

Агент — недоверенный автор кода. Он может ошибиться, может прочитать в тикете или в файле
инструкцию, которую подсунули (промпт-инъекция), а может просто сделать что-то странное. Цель
изоляции: даже в худшем случае потерять можно только его контейнер или машину. Файлы, диски,
ключи и аккаунты хозяина остаются недоступны.

## Что опасно в запуске прямо на Windows

| # | Дыра | Чем грозит |
|---|---|---|
| 1 | Верстак сам запускает `go test`, а тесты пишет агент | Код агента выполняется с правами пользователя: удалить файлы, прочитать ключи, запустить что угодно. Песочница Codex здесь не участвует |
| 2 | `git add/commit/status` на хосте в репозитории, который агент может менять | Хуки, fsmonitor и фильтры из `.git` выполняют команды при наших git-командах |
| 3 | Песочница Codex `workspace-write` ограничивает запись, но не чтение | Агент читает весь диск: `~/.ssh`, `~/.codex/auth.json`, токены других проектов |
| 4 | Авторизация Codex | Кто получил токен, тот пользуется аккаунтом |

Поэтому **живые запуски — только в изоляции**. Запуск на хосте оставлен для отладки самого
верстака за флагом `-unsafe-host`. Хуки отключены во всех наших git-командах, на это есть тест.

## Уровень 1: Docker (сделано 21.10.2026)

`verstak -probe` проверяет изоляцию изнутри контейнера, собранного так же, как для тикета:

```
pass  not root                                 uid 10001
pass  no capabilities                          CapBnd 0000000000000000
pass  no new privileges                        NoNewPrivs 1
pass  root filesystem read-only                open /home/agent/probe-write: read-only file system
pass  no block devices (disks, partitions)     []
pass  no host drives, no Docker socket         []
pass  go, gofmt and git in a login shell       /usr/local/go/bin/go /usr/local/go/bin/gofmt /usr/bin/git
pass  no direct way out                        dial 1.1.1.1:443: connect: network is unreachable
pass  proxy refuses other hosts                example.com: 403
pass  proxy lets the model through             chatgpt.com: 200
```

Тот же образ без флагов проваливает 7 проверок из 9 (проверка инструментов добавлена позже), то есть проверка их действительно различает.
Первый прогон тикета без логина: Codex дошёл до `api.openai.com` через прокси и получил 401,
запросы к `github.com` (проверка обновлений) прокси отклонил. После прогона не остаётся ни
контейнера, ни тома.

Docker Desktop уже стоит, работает на WSL2. Контейнеры живут во внутренней виртуальной машине,
диски Windows им не видны, если их не смонтировать.

- **Внутри контейнера всё, что исполняет код агента:** Codex, `go vet`, `go test` и git над
  клоном. На хосте остаётся только оркестратор, а он код агента не исполняет.
- **Никаких папок хоста внутри.** Цель попадает в контейнер git-бандлом (`git bundle create` с
  хоста, это только чтение). Результат выходит тоже бандлом (`docker cp`). Хост забирает его в
  отдельный репозиторий-приёмник с отключёнными хуками, и разработчик смотрит diff оттуда.
- **Флаги контейнера:**
  - пользователь не root;
  - `--cap-drop=ALL`, `--security-opt=no-new-privileges`;
  - корневая ФС только на чтение, `/tmp` в tmpfs, рабочий том на тикет;
  - `--pids-limit`, `--memory`, `--cpus`;
  - нет `--privileged`, нет устройств, нет сокета Docker.

  Удалить раздел диска из такого контейнера нельзя: блочных устройств там нет, прав root нет,
  диски Windows не видны.
- **Сеть.** Контейнер стоит во внутренней сети Docker без выхода наружу. Наружу ходит только
  прокси-контейнер, и только по белому списку адресов OpenAI. Модули Go вшиты в образ
  (`GOPROXY=off`), поэтому интернет для сборки не нужен.
- **Секреты.** Внутри только авторизация Codex, и это **отдельный аккаунт агента** (новая подписка
  Plus — его, не основная). Файл монтируется только на чтение. Даже если агент его прочитает,
  отправить его он сможет только на адреса OpenAI. Вариант строже: API-ключ с лимитом расходов.
- **Время жизни.** Один контейнер на тикет (`--rm`), том удаляется после выгрузки бандла.
  Таймаут на тикет; по таймауту контейнер убивается.
- **Образ** собирается локально: Go той же версии, Node, `@openai/codex` закреплённой версии.
  С хоста в образ ничего не копируется.

## Уровень 2: отдельная машина (потом)

На Windows 11 Home нет Hyper-V Manager, поэтому есть два варианта:

- **Облачная VM** под этот проект и только под него: ничего чужого на ней нет, хост с ней
  связан только через git (бандлы по SSH с ограниченным ключом). Даже побег из контейнера
  приведёт на пустую машину. Простой заморозкой.
- **Локальная VM** (VirtualBox): бесплатно, но живёт на той же машине и делит с ней ресурсы.

Переносим на машину, когда агент начнёт работать регулярно или по ночам без присмотра.

## Что остаётся

- **Побег из контейнера** через уязвимость ядра или Docker. Маловероятно, уровень 2 закрывает и это.
- **Вредный код в ветке**, которую разработчик примет сам. Diff нужно читать. Агент может
  переписать в своём клоне и защиты верстака (запретный список, коммит после проверок). Такие
  правки смотрим особо внимательно; в планах — пометка в отчёте «затронуты защиты».
- **Расход токенов.** Лимиты подписки, таймаут на тикет, число раундов.
